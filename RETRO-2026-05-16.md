### Class: `retry::dev-server-stale-modules` (count: 1 this run, **1 cumulative**)

### Class: `retry::spa-localstorage-init-script` (count: 1 this run, **1 cumulative**)

- **Event**: First implementation of `screens.js` used `page.evaluate(setItem)` AFTER `page.goto()`. React's `useState(() => localStorage.getItem(...))` initializer reads localStorage on mount — which happens BEFORE the post-load evaluate runs. So the SPA stayed signed-out for every shot.
- **Impact**: 14 identical "LoginScreen" screenshots; required rewrite to use `addInitScript` in the browser context before any navigation.
- **Fix**: `await context.addInitScript(() => localStorage.setItem(...))` before `context.newPage()`.
- **Status**: 1 cumulative, below threshold. Diff #3 proposed.

### Diff #3 — Add SPA-testing pitfall under §1 (Command-pattern constraints)

**Triggered by**: `retry::spa-localstorage-init-script` (1 occurrence)

```diff
+## 1a. SPA testing — localStorage initialization pitfall
+
+When testing an SPA with Playwright (or any browser automation):
+
+✅ `await context.addInitScript(() => { localStorage.setItem(...); })` BEFORE any `page.goto()`.
+   addInitScript runs in every new document context before the SPA's scripts, so React's
+   `useState(() => localStorage.getItem(...))` initializer sees the seeded values.
+
+❌ `await page.goto('/'); await page.evaluate(() => localStorage.setItem(...))`. The SPA already
+   mounted with empty localStorage; setItem fires after the snapshot. Subsequent navigations
+   inherit the stale React state — login screen captured for every shot.
```

**Justification**: an entire screenshot run was wasted before the addInitScript fix. Worth a callout.

**Anti-pattern check**: PASS

## F. Cross-cutting lessons

- **SPA test localStorage**: `addInitScript` before nav, not `evaluate` after
- **Telemetry persistence**: gitignored files don't survive re-clones; back up before recovery
