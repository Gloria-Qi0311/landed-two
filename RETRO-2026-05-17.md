### Diff #3 — Vite `.jsx`-before-`.tsx` extension-order pitfall (new §1b)

**Triggered by**: `unexpected_state::silent-extension-resolve-order` (cumulative: 1). Below threshold, but failure mode is silent (no warning, no error, bundle hash unchanged) — documentation is cheap insurance.

```diff
+## 1b. JSX → TSX migration with same basename (Vite)
+
+When converting a `.jsx` to a `.tsx` with the same basename, **delete the old `.jsx` file in the
+same commit** (`git rm path/foo.jsx`). Vite's default `resolve.extensions` order puts `.jsx`
+BEFORE `.tsx`, so an extensionless import like `from './foo'` keeps resolving to the old `.jsx`
+silently — bundle hash unchanged, no warning, no type error. Verify via bundle-hash diff
+before/after the swap.
+
+Note: `Bash(rm:*)` is denied in the recommended allowlist — use `git rm` (a tracked git
+operation, not a destructive filesystem `rm`).
```

**Anti-pattern check**: PASS — explicitly endorses the `rm:*` deny rule.
