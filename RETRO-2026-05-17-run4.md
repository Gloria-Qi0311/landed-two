## E. Proposed SKILL.md edits

### Diff #1 — Negative-space probes for the sub-agent / self-review checklist

**Triggered by**: 4 boundary-contract bugs in Run 4 + analogous bugs in Runs 2-3 (#23/#24 schema mismatch, #31/#32 chrome.sendMessage protocol). Meta-pattern: every sub-agent catch that mattered was one of four families. **Cumulative: 7+ events across Runs 2-4.**

The 9-point checklist (Run-3 Diff b) is **positive-space**: "does X do Y? is it tested? does the build pass?" All 4 Run-4 catches are **negative-space**: "what state could break this despite X doing Y?" Adding named probes for the four recurring families turns negative-space coverage from "hope the sub-agent thinks of it" into a deterministic check.

```diff
--- a/SKILL.md (§2 step 9 — Independent review)
+++ b/SKILL.md
@@ Step 9 ends with: "Post a brief summary..." @@
 review on the PR (single-line `--body` or `--body-file`).
+
+   **Pre-prepared checklist — include "negative-space" probes.** The 9-point rubric in
+   the PR body (per Run-3 retro habit) catches positive-space things ("does X do Y?
+   is it tested? does the build pass?"). It systematically misses **boundary-contract
+   mismatches** — bugs where each side is internally correct but the contract between
+   them is wrong. Across Runs 2-4, every sub-agent catch that mattered was one of these
+   four families. Add a probe for each to every checklist:
+
+   1. **Producer-output × downstream-consumer trust** — if the diff adds/changes a
+      parser, classifier, mapper, or selector: what does the *downstream* code do with
+      its output? Could a too-broad match / unexpected shape / null cause a wrong (not
+      just missing) side-effect downstream? Example (PR #70): a too-broad fallback
+      selector emitted a phantom event the pipeline trusted.
+   2. **Function precondition × silent side-effect** — if the diff has a drain/clear/
+      reset path gated on a derived value, check the *source* field of that derivation,
+      not just the assembled result. Empty-rows-as-side-effect-of-bad-input is a silent
+      footgun; preserve state when the precondition is wrong. Example (PR #72): missing
+      `session.user.id` mapped every row to null and `clearPending`'d the queue.
+   3. **Producer/consumer state-machine** — if the diff reads a sentinel/flag set
+      elsewhere: who clears it, when, and is there a moment the consumer can read the
+      stale value between the user-action-that-should-clear-it and the producer-clear?
+      Clear sentinels on the user action that fixes the condition, don't wait for the
+      async producer. Example (PR #73a): sentinel survived sign-out and re-shown on
+      sign-in.
+   4. **Async ordering / subscription registration** — if the diff registers a listener
+      AND reads an initial value asynchronously: the listener MUST be registered BEFORE
+      the await; gate the post-await setter with a "change already arrived" flag.
+      Example (PR #73b): listener-after-`get` race.
+
+   These same four prompts are the right fallback for self-review when sub-agent is
+   rate-limited.
```

**Anti-pattern check**: PASS — additive, no deny rule touched, no safety bypass, strictly tightens not loosens.

## F. Cross-cutting lessons

1. **Scope-cut works.** 3/5 Run-4 tasks scope-cut; zero user intervention; all 3 documented followups. Run-3 Diff (a) is empirically validated.
2. **Pre-prepared checklists work, but are positive-space.** Run-3 Diff (b) ensured every PR had a rubric; sub-agent used it in every review. But sub-agent caught bugs *not on the rubric* in every case. Negative-space probes (§E Diff #1) close that gap.
3. **Sub-agent ROI scales with boundary count, not LOC.** Run-3 PRs were small/scaffold (33% catch ratio); Run-4 PRs were larger and more integrative (80% catch ratio). More boundaries → more contract surfaces → more catches. Useful framing when sizing PRs.
